# Semiconductor Yield Prediction and Excursion Analysis

Predict pass/fail yield for wafer-fabrication production runs from sensor data,
surface root-cause candidate signals, and monitor live runs for excursions —
served behind a FastAPI REST API in Docker.

## Data provenance: REAL data

This project uses the **real SECOM dataset** from the UCI Machine Learning
Repository (McCann & Johnston, 2008; donated 2008-11-19; CC BY 4.0):

- 1,567 production runs × 590 columns (column 0 = timestamp, columns 1–589 =
  sensor signals), with heavy missingness (41,945 missing entries)
- Labels: `-1` = pass, `+1` = fail → **104 fails (6.6%)**, 1,463 passes
- Nothing is synthetic. The metrics below were produced by running
  `scripts/train.py` on this data (seed 42, deterministic).

## Methodology

**1. Leak-free preprocessing** (`src/secom_yield/preprocessing.py`)
`LeakFreePreprocessor` drops signals with >50% missing values (fit data only),
drops constant signals, and median-imputes — all statistics learned from the
*training fold only*. Because it sits inside an sklearn `Pipeline`, every CV
fold re-learns its own kept-signal set and medians: no train-test leakage.
A dedicated test asserts imputation uses train-only medians.

**2. Yield prediction** (`src/secom_yield/modeling.py`)
Gradient-boosted trees (XGBoost when installed; here sklearn's
`HistGradientBoostingClassifier`, since the XGBoost wheel would not download
in this environment) vs. a logistic-regression baseline, compared with
5-fold stratified cross-validation on ROC-AUC.

**3. Root-cause analysis** (`src/secom_yield/rootcause.py`)
Per-signal Mann-Whitney U tests (fail vs. pass) with Benjamini-Hochberg FDR
control at 5%, cross-checked against mean-|SHAP| rankings from the fitted
model. Candidates are reported explicitly as **correlations for process
engineers to confirm** — not proven causes.

**4. Excursion monitoring** (`src/secom_yield/excursion.py`)
Runs are time-ordered; the first half is the in-control reference period.
An Isolation Forest fitted on the reference scores later runs, and Shewhart
3-sigma control charts on the top-3 attributed signals flag excursions.

## Results (from the actual training run)

| Model | 5-fold CV ROC-AUC (mean ± std) | Fold scores |
|---|---|---|
| Gradient-boosted trees (`HistGradientBoostingClassifier`) | **0.704 ± 0.036** | 0.644, 0.720, 0.741, 0.735, 0.681 |
| Logistic regression (baseline) | 0.663 ± 0.030 | 0.680, 0.645, 0.679, 0.613, 0.696 |

Leak-free signal selection kept **445 of 589** sensor signals per the
>50%-missing and constant-signal rules (144 dropped); the kept set is
re-learned inside every CV fold. Attribution via SHAP
(`shap.TreeExplainer`, 500 samples).

Root-cause screen: **25 signals significant** at BH-FDR 5%; the top 25 by
SHAP attribution are saved to `artifacts/root_cause_candidates.csv` with the
correlation-not-causation disclaimer attached to every row. Top candidates
include `s33`, `s59`, `s247` (see CSV for p-values and ranks).

Excursion monitoring: **784 monitored runs** (second chronological half;
783 reference), **25 flagged by Isolation Forest** (contamination 5%),
**10 runs with 3-sigma Shewhart breaches** on the top-3 signals
(`s33`, `s59`, `s130`).

## How to run

```bash
python -m venv .venv && source .venv/bin/activate
pip install -r requirements.txt

python scripts/download_data.py   # fetch SECOM from UCI (~5 MB)
python scripts/train.py           # full pipeline; writes artifacts/metrics.json
PYTHONPATH=src pytest tests/ -q   # 23 tests
```

Serve the API (needs `artifacts/` from `train.py`):

```bash
PYTHONPATH=src uvicorn secom_yield.api:app --port 8000
```

Or with Docker (downloads data and trains during the build):

```bash
docker build -t secom-yield .
docker run -p 8000:8000 secom-yield
```

## API

- `GET /health` → service status, model id, CV ROC-AUC, feature count
- `POST /predict` → `{"signals": [590 floats, null allowed]}` →
  `{"fail_probability": 0.13}` (signals = time + 589 sensor values, in
  `secom.data` column order; `null` = missing)
- `POST /excursion` → same input →
  `{"anomaly_score": …, "is_anomaly": …, "n_chart_breaches": …,
    "breached_signals": […], "is_excursion": …}`

```bash
curl -s localhost:8000/health
```

## Notes and limitations

- Class imbalance is severe (6.6% fails); ROC-AUC is reported, but for fab
  use you would tune the decision threshold on precision/recall for the fail
  class rather than using 0.5.
- SHAP values are computed on the fitted tree model; the Mann-Whitney screen
  runs on median-imputed data, which is standard but can attenuate p-values.
- The Isolation Forest reference period is the first chronological half of
  the data — a modeling choice, not a labeled "known good" period.
